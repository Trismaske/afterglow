# Plan v0.6 — The RAW pipeline + Lightroom companion plugin

*The release plan for desktop v0.6, answering `docs/Feedback_v0.6.md`.
Evidence and decision history: `docs/Investigation_v0.6.md` (delete both once v0.6 ships and PLAN.md absorbs what remains).
Version 0.5.0 → 0.6.0, tag `desktop-v0.6.0` (`scripts/release-preflight.mjs` requires the full-semver desktop tag `desktop-v${version}`), branch `initial`.
Ridealong: the already-committed windowed-settings/app-icon and desktop-hardening work since `desktop-v0.5`.*

## What ships

RAW files enter the slideshow, rendered with the user's edits by the editor that owns them:

1. **darktable edits** (`X.ext.xmp`, `darktable:` namespace) → `darktable-cli` render. Faithful.
2. **RawTherapee edits** (`X.ext.pp3`) → `rawtherapee-cli` render. Faithful.
3. **Lightroom edits** (`X.xmp`, `crs:` namespace, incl. `.acr` AI masks) → the **Afterglow companion plugin** running inside the machine's own LR Classic, always against a **dedicated Afterglow render catalog** (import → forced sidecar read → `LrExportSession`); user catalogs are never imported into or metadata-read. Faithful; requires LR installed + running (Afterglow manages LR's lifecycle; jobs defer while a user's own LR session is open).
4. **No edits / no editor** → embedded camera preview, honestly labeled, behind a user setting (show labeled [default] / only if full-res preview / skip). Same setting family covers unrenderable edits (crs present, no LR).

Plus, the **just-in-time ephemeral render pipeline** (decided 2026-07-26, replacing an earlier persistent-cache design): the show maintains a moment-aware **look-ahead queue** (**depth is a setting, default 10 slides** — renders start this many slides ahead so →-navigation is ready too; when the mix engine picks a moment, all its members queue at once so they land as the moment plays, even beyond the depth). A RAW entering the look-ahead resolves, in order, to:
1. its **fresh JPEG sibling** (same basename, same folder or the `JPEG\` subfolder; fresh = newer than every edit dependency, dependency digests unchanged, **and** the source RAW's stored mtime/size identity unchanged) — shown directly, no render;
2. a **JIT render** into an ephemeral buffer — deleted once the item leaves the recent-history window (so ←-navigation stays instant), re-rendered on its next appearance; compute is deliberately spent freely, the machine is idle while the screensaver runs;
3. its **stale sibling**, labeled "outdated edit" (never shown silently) — for photos whose edits **cannot be rendered** (no LR, AI-excluded), tiers 3–4 are governed by the unrenderable-edits fallback setting: `skip` skips outright, stale siblings and previews appear only when the setting permits — **and auto-flagged into the flag queue for review** — the flag entry targets the **sibling JPEG's own path** (a defined exception to source-path routing: the review subject is the export, not the RAW) and carries **automatic provenance** (distinguished from manual flags in the entry itself). Automatic stale flags have a lifecycle: they are **removed automatically when the sibling becomes fresh again** (re-exported/rewritten so mtime+digest are current) and can be dismissed by the user — a dismissal is durable for the *current* stale state (recorded against the **complete freshness identity** — sidecar digests, embedded identity, RAW mtime/size; rescans, re-appearances, and restarts never re-add it) and only a subsequent change to any part of that identity may flag the sibling anew; manual flags are never auto-removed. This builds the work list for the eventual "delete the exports" cleanup without ever offering deletion of a now-fresh export;
4. the embedded camera preview / skip — governed by the **unrenderable-edits setting** when the photo has edits that cannot be rendered, and by the **unedited-RAW setting** only for truly unedited RAWs.

A JPEG sibling is stale when older than **any edit dependency**, when a dependency's stored digest changes, **or when the source RAW's own identity (mtime/size) has changed since the sibling was last judged fresh** — a replaced sidecar-free RAW must not keep serving its old export: for sidecar-file edits that means the `.xmp`/`.pp3`/`.acr` files; for RAWs whose edits are **embedded** (e.g. DNG embedded XMP — no sidecar files exist) it means the container's mtime/size and the extracted-XMP digest. Dismissal state keys to the **complete freshness identity** — sidecar digests, embedded identity, and the RAW's mtime/size — so a sidecar-free RAW replacement creates a distinguishable new stale state that may re-flag (tested). Digests are persisted in the index, so mtime-preserving sync rewrites of sidecar files are caught. When the next slot's item isn't ready, the show substitutes the next ready item or **holds the current slide a few seconds** (the settings UI says so, so nobody is surprised); a substituted-past item is **deferred, not discarded** — it stays in the look-ahead and re-slots when its render completes, and only if the playlist drops it entirely does normal invalidation disposal apply. Rendering is **strictly JIT for the look-ahead — no background bulk-crunch** of the stale backlog.
Also: RAW+JPEG pair de-dup (a RAW and its sibling are one photo in the draw), FUSE/network-mount exclusion (new folder selection **and** persisted folders validated at startup before any traversal), and the feedback fix: the flag queue reachable from the settings screen.

Explicitly **not** in v0.6: acting on flags (v0.7 organizer), refreshing the user's own exported JPEGs in place (the plugin renders only into Afterglow's ephemeral buffer; in-place refresh is organizer territory), HEIC, Lightroom preview-cache extraction (rejected — see PLAN.md).

## Verified constraints the implementation must honor

- **darktable-cli**: private `--configdir` per install (default configdir deadlocks under flatpak PID namespace; stale `.lock` files after crashes must be cleaned); renders serialized (concurrency 1 — parallel configdirs contend badly); **output path must use forward slashes on Windows** (darktable's filename-template engine eats backslashes); `--library :memory:`; sidecar passed explicitly.
- **rawtherapee-cli**: `-S` renders only-if-sidecar (explicit error otherwise — clean detection); Windows install dir is versioned (`RawTherapee\5.12\`) — discovery globs it; Linux discovery covers native + flatpak (`org.darktable.Darktable` / `com.rawtherapee.RawTherapee` with `--filesystem` for paths outside host scope).
- **Render budget** (verified on the deployment machine, i5-11400): 3–8 s per photo. The look-ahead absorbs it: renders start well before their slot, and when one isn't ready the show substitutes the next ready item or holds the current slide a few seconds — a brief wait is acceptable (and documented in settings), an indefinite block is not.
- **Lightroom plugin**: import alone loads no sidecar edits — `photo:readMetadata()` is required and works, and its confirmation prompt is **solved** (suppressed durably via the preference keys in P4); the AI-updates dialog is the one remaining dialog case (P4). LR GUI must be running. **Catalog isolation is absolute**: Afterglow launches LR minimized with its own render catalog and gracefully closes only instances it launched (never force-kill; a blocked close is logged and left alone). A user's own LR session (any other catalog) is never reused — imports and forced metadata reads there could pollute the catalog or overwrite newer unsaved edits — so LR jobs defer, surfaced honestly, until the user's session closes. **One opt-in exception to the close policy** (`close-Lightroom-on-screensaver-start`, default off): only on a **screensaver-triggered launch** — which requires a **distinct provenance signal in launch parsing**: today `parseLaunchMode` collapses win32 `/s` and manual `--show` into one mode, so `LaunchInfo` gains a `screensaver` flag set only by OS idle triggers (`/s`; never the Start button or `--show`, since the user may be active), **and that provenance must survive the single-instance handoff**: `/s` arriving while an instance is already open loses the lock and reaches the existing process via `second-instance`, which today ignores non-settings launches — the forwarded argv must start the show with screensaver provenance intact (gated) — a user-owned session may be closed gracefully — a blocked close falls back to deferral, force-kill never happens — after which Afterglow launches its own render-catalog instance.
- **Detection rules**: `X.ext.xmp` + `darktable:history_end>0` → darktable; `X.ext.pp3` → RT; `X.xmp` + `crs:HasSettings` → LR; else embedded edit-namespace XMP; else unedited. When a RAW carries **valid sidecars from more than one editor** (plausible mid-migration, e.g. an RT-era `.pp3` beside a newer darktable `.xmp`), the **newest sidecar wins** (last-edited editor owns the current look) — never a fixed type priority — and the conflict is surfaced in a diagnostics list rather than passing silently; both sidecars stay untouched, so a wrong pick is fully recoverable. Ordering uses sidecar mtimes, falling back to which sidecar's stored digest changed most recently (the index remembers digest transitions); when genuinely unordered (equal mtimes, no digest history) the photo is **not rendered by a guessed editor** and **bypasses the fresh-sibling tier too** (a sibling JPEG cannot be attributed to an editor either): its sibling or preview shows with an "ambiguous edits" label and the conflict surfaced, until the user edits again or resolves it. **Every multi-editor conflict — ordered or not — bypasses the fresh-sibling tier**: a JPEG cannot be attributed to the winning editor (it may have been exported through the loser without touching that sidecar), so ordered conflicts go straight to the winning editor's JIT render, with the sibling available only as the labeled fallback. **Embedded edit namespaces participate in the same selection**: a DNG carrying embedded `crs:` plus an external sidecar compares the embedded identity's recency (container mtime / extracted-XMP digest transitions) against sidecar mtimes under the same newest-wins rule and appears in the same diagnostic. The conflict gate covers these display paths, ordered and unordered, sidecar and embedded. darktable sidecars with `xmp:Rating="-1"` (rejected) are excluded from rotation. crs XMPs are **never** fed to darktable-cli (verified silently ignored).
- **Formats**: NEF/CR2/CR3/ARW/DNG are first-class — each render-verified through the pipeline before release (NEF/ARW already verified; **CR2/CR3/DNG live-render verification is part of P2's gate**; CR3 is the family's current-camera format — non-negotiable). Other RAW extensions are accepted but documented untested.

## Phases

Each phase lands with its tests and doc updates; gates are demo-able.

**P1 — Detection core (pure).**
`main/raw/detect.ts`: scan-result classifier → `{ editor: 'darktable'|'rawtherapee'|'lightroom'|null, sidecarPaths, embedded: { containerMtime, containerSize, xmpDigest } | null, conflict: { editors, chosen, reason } | null, rejected }` from sidecar presence + namespace sniff + embedded-XMP scan. `sidecarPaths` lists **every** edit dependency (an LR asset can have `X.xmp` *and* `X.acr` together); `embedded` carries the identity that drives freshness/dismissal when edits live inside the container (no sidecar files exist); `conflict` carries the surfaced multi-editor diagnostic — downstream freshness, dismissal, and diagnostics consume exactly this contract.
Embedded XMP + preview extraction need a tool on all platforms: **(autonomous)** bundle per-platform `exiftool` standalone binaries (industry standard; also fixes the deployment machine, which has none) rather than hand-writing TIFF/CR3 parsers; revisit only if bundle size is unacceptable.
Gate: unit tests over fixture sidecars (real darktable/RT/LR samples, DJI factory-XMP negative case), **plus the full multi-editor conflict contract**: fixtures covering ordered conflicts in both directions (selected editor + surfaced diagnostic), genuinely unordered conflicts (equal mtimes, no digest history → labeled fallback, never a guessed editor), the fresh-sibling bypass during any conflict, and embedded-vs-sidecar conflicts (embedded identity recency participating in newest-wins) — a fixed-priority or sibling-leaking resolver must fail this gate.

**P2 — Renderers + look-ahead scheduler (main).**
`main/raw/renderers.ts`: `execFile` wrappers (darktable, RT, exiftool preview) with per-editor discovery (PATH, flatpak IDs, Windows registry/default dirs incl. versioned RT) surfaced in settings.
The **look-ahead scheduler** watches the playlist's upcoming window (moment-aware: a chosen moment queues all members immediately), resolves each RAW per the tier order (fresh sibling → JIT render → labeled stale sibling → preview/skip), and renders serially into the **ephemeral buffer**: entries keyed by full render identity `(path, RAW mtime+size, every edit-sidecar content digest, artifact route + renderer/plugin version, output-affecting settings, output size)` so a wrong-route or outdated artifact can never answer, **Buffer lifecycle**: entries are deleted when their item leaves the recent-history window (←-navigation stays instant); during-show usage is bounded by **(history size + look-ahead depth + largest queued moment) × render size** — the working set is history plus everything prefetched; **abandoned work is disposed too** — when a look-ahead item is invalidated (playlist hot-swap, moment skip) its pending job cancels, a late-arriving artifact is deleted on arrival, and an **already-completed prefetched artifact is deleted immediately** unless still referenced — with a small library the endless playlist repeats identities inside look-ahead + history, so jobs coalesce per render identity and an artifact is deleted only when **no** history or look-ahead occurrence references it; the whole buffer is wiped when the show ends; and a startup sweep removes crash orphans. **External writers are epoch-scoped**: each run stamps a run epoch and the LR plugin writes artifacts only into that epoch's directory, so an export completing after teardown or a crash lands in a dead epoch — sweeps delete every non-current epoch, and the shutdown/adoption handshake quiesces or re-homes in-flight LR jobs before the final sweep (teardown-during-export and crash-restart-during-export are gated) — no LRU, no size-cap setting, no "clear cache" UI, and no path by which the buffer can quietly become a persistent cache.
**Disk-space floor**: before each render the scheduler checks free space on the buffer volume (~2 GB floor); below it, rendering pauses — the show continues on siblings/previews/skip per settings with an honest "RAW rendering paused: low disk space" status (loud once, never per-photo), auto-resuming when space recovers; a mid-write `ENOSPC` counts as a failed render for that item (falls through to the next tier).
Freshness rules: sidecar *files* are always content-digested (cheap; catches mtime-preserving sync rewrites); embedded XMP in DNGs is re-extracted when the container's mtime/size changes. **Documented limitation**: a RAW rewritten with both mtime and size preserved is **undetectable** — no persisted signal changes, and no rescan or index rebuild can distinguish it (there is deliberately no RAW-content digest); classification, sibling freshness, and renders keep reflecting the old content until the file's observable metadata changes. Accepted: real editors update mtime on save.
Renderers hide behind an interface so tests use fakes; live renders verified by a manual smoke script run on lenny + home-pc, **covering every first-class format not yet verified: CR2, CR3, and DNG** (NEF/ARW are already verified).
Gate: a simulated show with a slow fake renderer substitutes-or-holds (bounded) and never blocks indefinitely, with the substituted item re-slotting when ready and disposed only when dropped; a repeated-item test (library smaller than look-ahead) proves coalesced jobs and no premature artifact deletion; moment pre-queueing proven (all members requested the moment the moment is chosen); buffer identity unit-tested with **an isolated case per key discriminator, each varied alone**: path (two RAWs never share an artifact), RAW mtime only, RAW size only, sidecar digest-only rewrite (mtime and size preserved), artifact route (a preview never answers for an editor render), renderer/plugin version bump, output-setting change, and output size; and the buffer lifecycle verified: deletion on history-exit, cancellation + late-artifact disposal + immediate deletion of already-completed prefetched artifacts for invalidated look-ahead items (hot-swap and moment-skip cases), wipe on show teardown, startup orphan sweep, and the disk-floor pause/resume path (rendering pauses below the floor with the status surfaced, show continues on fallback tiers).

**P3 — Slideshow integration.**
Scanner accepts RAW extensions; `afterglow://` continues to serve browser-decodable source media (JPEG/PNG/WebP + videos, per the existing containment) and additionally the contained render-buffer/preview roots — **RAW originals are the only thing never served**.
**Source identity and display URL become distinct playlist fields**: a RAW slide displays its render-buffer/preview URL, but overlay info, flags, and queue entries always target the original RAW path (today the renderer passes the display URL to `getItemInfo`/`addFlag`, which would reject or mis-record buffer paths). **One defined exception**: the automatic stale-export flag targets the sibling JPEG's path, because the export itself is the review subject (v0.7's family-lockstep operations get a matching sibling-only delete action for these entries).
Pair de-dup incl. `JPEG\` subfolder + staleness rule (stale siblings additionally auto-flag into the flag queue); unedited/unrenderable-RAW setting + "camera preview" / "outdated edit" overlay labels.
New settings in this phase: unedited-RAW handling, **unrenderable-edits fallback (show labeled sibling/preview [default] / skip — governs tiers 3–4 whenever edits exist but cannot be rendered: LR unavailable, AI-excluded, ambiguous conflicts)**, **video sound (default muted)**, **close-Lightroom-on-screensaver-start (default off = defer; applies only to screensaver-triggered launches, never manual starts)**, **look-ahead depth (default 10, clamped 3–50)**, **history size (default 200, clamped 20–1000** — one value governing both how far ← reaches and how long rendered artifacts are retained; replaces the navigator's hard-coded 200**)**, and the settings copy noting a slide may hold a few extra seconds while the next photo renders. Clamps enforced in `main/settings.ts` like the existing numeric settings.
FUSE/network-mount validation applies to **persisted settings at startup, before any path traversal or scan** (a hung mount must not wedge launch; a recovery screen lets the user remove the folder) as well as to new folder selection.
**Zero-ready cold start**: on an all-RAW library with settings that exclude previews (`skip` / `only full-res`), nothing may be ready at show start — the show must enter a waiting state ("rendering your library…") and hot-swap slides in as the first renders land (today `startShow` reports "no images" and later updates are ignored because no swappable playlist exists).
The waiting state must be **terminal-aware**: when no viable render job remains (editors unavailable, previews below threshold, all renders failed), it becomes an actionable "nothing can display with current settings" message naming the setting to change — never an infinite spinner, especially under `--show`.
Gate: headless smoke over a fixture tree with RAW+sidecar pairs shows rendered/preview/skipped per setting; flagging a RAW slide records the RAW's source path (not the cache URL); the zero-ready cold start reaches a running show without restart; a focused test drives the terminal branch (no viable render job — editors unavailable / renders failed / previews below threshold) to the actionable "nothing can display" message, never the spinner; a **protocol-boundary assertion** proves browser-decodable sources and contained cache/preview artifacts load while RAW source URLs are refused (scanner and protocol share `isMediaFile`, so widening one must not open the other); an **injected startup test** proves a rejected persisted mount reaches the recovery screen with zero `realpath`/`readdir`/`stat` calls against it (startup currently realpaths media roots before any UI); and a **digest-only sibling test** changes sidecar content with mtime and size preserved (plus an embedded-edit variant: a DNG with no sidecar files whose container changes, and a sidecar-free variant: a replaced RAW whose unchanged sibling must go stale) and verifies the sibling is marked stale, auto-flagged (with automatic provenance), and superseded by a JIT render on its next appearance; re-exporting the sibling then clears both the stale marker and its automatic flag while manual flags survive; and dismissing an automatic flag while the sibling stays stale is durable across rescan, re-appearance, and restart, with **post-dismissal cases for every identity discriminator** — a subsequent sidecar digest change, embedded-identity change, and RAW mtime/size change must each be able to re-flag. The stale marker is **durable and owned by the sibling**: it persists across restarts and clears only when the sibling file itself changes (re-exported/rewritten) — an ephemeral render satisfies display but never clears it, so after any restart the unchanged sibling is still stale (labeled), never silently laundered fresh.

**P4 — Lightroom companion plugin (`apps/lightroom-plugin/`).**
Hand-rolled Lua, file-based job queue (Afterglow writes job JSON into a watched folder; plugin polls via `LrTasks`, imports, forces sidecar read, exports into Afterglow's render buffer, writes result JSON).
**The plugin guards every claim by catalog identity**: before touching any job file it verifies `activeCatalog()` is Afterglow's dedicated render catalog and otherwise ignores the queue entirely — job files and the plugin survive restarts, so without this check a stale job observed while a user's catalog is open would import and `readMetadata()` there, violating isolation. The stale-job/user-catalog restart scenario is gated.
**Zero-dialog operation is a hard requirement** (screensaver runs unattended; any interaction stops it — Tristan, 2026-07-26).
Spike-verified (2026-07-26) constraints the implementation builds on:
- The `readMetadata` prompt fires even for fresh imports but is **durably suppressed** via LR prefs: `doNotShowPrompts` must contain `AgLibrary_readMetadata` with `AgLibrary_readMetadata = "read"` — onboarding verifies/pre-seeds these keys (verified: first call blocked on the dialog, every later call silent and instant).
- The **"AI Updates Recommended" dialog** appears at export for AI-mask photos needing local recompute (`AIUpdateWarning_shouldUpdateAffectedPhotos` persists the checkbox, but dialog suppression for *new* affected photos is unproven). P4 must resolve it: find its suppression pref / pre-trigger the AI update programmatically after `readMetadata` — and if it cannot be suppressed, **AI-mask photos are excluded from unattended LR rendering** (they show the labeled stale JPEG/camera preview per the fallback setting) until an explicit user-initiated **attended maintenance pass** unlocks them: the pass's product is durable **Lightroom state**, not artifacts — it performs the AI-settings updates in the render catalog (accepting the dialog per photo once), after which those photos re-enter the normal unattended JIT tier dialog-free. **Unlocks key to the photo's full edit identity** (sidecar digests + embedded identity): a later sidecar/embedded change re-excludes the photo until unlocked again — a stale unlock must never let the dialog reopen unattended (the edit-change → re-excluded → re-unlock sequence is gated). The pass never runs during the show, and its unlock effect is gated (photo excluded → attended update → next unattended show renders it).
- SDK plumbing (all learned the hard way): catalog writes need a fresh `LrTasks.startAsyncTask` per job **and** a `{ timeout }` on `withWriteAccessDo`; use `LrTasks.pcall`, never plain `pcall`, around anything that yields; `LrForceInitPlugin = true` or the init script may never run; job-file claims must be **verified atomic** (an unverified claim rename caused a runaway respawn loop in the spike — claim, confirm the claim succeeded, and de-duplicate in-process before processing).
Afterglow side: LR discovery; launch-minimized **with the dedicated render catalog** on show start when LR-owned jobs are pending; graceful close of Afterglow-launched instances on show end; defer jobs (surfaced honestly) whenever a user's own LR session is open.
**Crash recovery**: if startup finds an LR instance already running against Afterglow's own render catalog (an orphan of a crashed run — neither user-owned nor launched by this run), the new run **adopts** it: stale job claims are reset, pending job files reconciled, and if adoption fails the instance is closed gracefully; the crash-restart path is gated.
**The render catalog is bounded and disposable**: it is Afterglow-owned throwaway state — when the render catalog is not open in any LR instance **(a precondition for every reset trigger — bound exceeded or plugin-version change alike; an upgrade arriving while a crashed run's orphan still holds the catalog waits for adoption/close first, and that recovery path is gated)** and a trigger fires (bound exceeded: photo count or on-disk size incl. previews; or plugin version change), Afterglow deletes the **complete catalog file family** — `.lrcat`, its `.lrcat-data` companion, preview folders, and any helper files beside them — and starts fresh (imports are cheap metadata operations, so a reset costs only re-import on next use). It never grows indefinitely. **Reset interaction with AI unlocks** (relevant only if the AI dialog proves unsuppressible): attended AI-update state lives in the catalog, so a reset forfeits it — Afterglow tracks the unlocked set, returns those photos to excluded-until-attended-pass, and surfaces that honestly (never silently); the bound is sized generously so resets stay rare, and the combined reset-after-unlock scenario is gated.
Gate: end-to-end on home-pc — start a show over a library containing a crs-edited CR3 and watch the look-ahead scheduler render and display it with **zero dialogs and zero manual interaction**. For an AI-mask photo the gate accepts either outcome of the dialog investigation: a dialog-free render, **or** verified labeled exclusion from the unattended path (with any attended maintenance pass demonstrated strictly outside the show). Either way, the show itself never sees a dialog.
The **isolation branch is gated too**: with a user's own catalog open in LR and the setting off, verify jobs defer — no import, no `readMetadata`, and Afterglow neither closes nor force-kills that instance. With the opt-in setting on, verify the graceful close on a screensaver-triggered launch, that manual launches never close a user session, the deferral fallback when the close is blocked, and that force-kill never occurs. The **catalog bound is gated too**: exceed it with LR closed and verify the catalog + previews are deleted and the next job re-imports into a fresh catalog.

**P5 — Release.**
**Plugin distribution**: the `.lrplugin` ships inside the app package (electron-builder `extraResources` — today only `dist/**` + `package.json` are packaged), and on first run Afterglow **copies it to a stable per-user location** (`<userData>/lightroom-plugin/`) and refreshes that copy on version change — onboarding registers the stable path, never the bundle path (the portable build unpacks `extraResources` into a temp dir that vanishes on exit, which would silently break LR's registration). Onboarding: settings shows the stable path + "add it in LR: File → Plug-in Manager → Add" with per-editor status; LR has no headless plugin install.
**exiftool distribution**: the per-platform exiftool payload (P1's bundling decision) ships the same way — `extraResources`/`asarUnpack` per platform for NSIS, portable, AppImage, and deb — and the clean-install gate exercises embedded-preview extraction from each packaged build (nothing in `dist/**` carries it today).
Queue-access ridealong (settings-screen "Flag queue (N)" button + `Q` accepted there, on the new count/change IPC scoped in `docs/Feedback_v0.6.md`); README + in-app tier messaging (the honesty ladder, per-editor availability); version bump, tag `desktop-v0.6.0`, CI artifacts, SHA-256 manifests; PLAN.md roadmap updated; Feedback/Investigation/Plan docs deleted post-ship.
Gate: **clean-machine install** (not the dev prototype) → onboarding → LR tier renders; installer smoke on home-pc; soak restarts with RAW folders enabled.

## Risks

- **The AI-updates dialog proves unsuppressible** → AI-mask photos are excluded from unattended LR rendering (labeled fallback display) and handled by the explicit attended maintenance pass; the rest of the LR tier stays fully unattended (the metadata prompt is already solved via pref keys). Reduced value for heavy AI-mask users, never a broken screensaver.
- **CI cannot run editors** → renderer interfaces + fakes in CI; live-render smoke is a documented manual step on the two known machines.
- **CR3 embedded preview is only 1620×1080** → acceptable behind the labeled-preview setting; the plugin covers the edited CR3s that matter.
- **Slow relay to home-pc for remote dev** → prefer running scripts on the machine (SSH) over transferring files.
