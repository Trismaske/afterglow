# Plan — next versions (drafted 2026-07-18)

Response to [Feedback_20260717.md](Feedback_20260717.md) (first tester round against desktop v0.4 / mobile m0.4). All feedback is actionable now; this plan packs it into **one release per app — desktop v0.5 and mobile m0.5** — and records the roadmap shifts that follow. (An earlier draft split each train into two releases; merged per Tristan's call on 2026-07-18. [PLAN.md](../PLAN.md)'s roadmap is updated to match.)

**Roadmap impact in one line:** desktop v0.5 becomes the feedback release including screensaver integration (pulled forward from v0.8 — testers' loudest ask); the RAW pipeline and everything after shift down by one. Mobile m0.5 takes the entire feedback round including custom scopes and deck zoom.

## Desktop v0.5 — "Feedback: control, navigation, screensaver"

UX fixes plus the screensaver button. Files referenced are under `apps/desktop/`.

### Launch & exit behavior
- **Manual launch opens the settings screen**, not the slideshow. Today `main()` in `src/renderer/index.ts` jumps straight to `startShow()` whenever folders are configured — that's the "couldn't get back to settings" complaint. New behavior: manual launch → settings screen with a prominent **Start slideshow** button; a `--show` CLI flag launches straight into the slideshow (this flag is also the screensaver entry point below).
- **Any key/mouse exits the slideshow back to settings** when the app was manually launched, instead of quitting (change the exit arbiter's action in `src/renderer/exit.ts` / `index.ts`). When launched with `--show` (screensaver mode), exit still quits the app. Flag keys and nav keys remain exceptions, as today.
- **Keep the OS screensaver/display-sleep away while the slideshow runs** — `powerSaveBlocker.start('prevent-display-sleep')` in `src/main/index.ts`, stopped when the show stops. Directly answers "prevent existing screensaver when afterglow is not set as default."

### Slideshow navigation
- **←/→ = previous/next photo, ↑ = restart current moment, ↓ = skip to next moment.** The `Slideshow` class (`src/renderer/slideshow.ts`) is currently fire-and-forget with only `start()`/`stop()`; it needs a seek API plus a history back-buffer over the playlist (`src/renderer/playlist.ts`, `smart.ts`). Nav keys reset the auto-advance timer and must be excluded from the exit arbiter.
- **Shortcut hints in the overlay**: extend the overlay with a compact key legend (O · Q · S · D/E/M/R/N/T · arrows). Also show the legend for a few seconds when the slideshow starts.

### Flags
- **Two new flag types**: `rename` ("Need to rename") and `date` ("Need to update date"). One flag each rather than a combined one — the queue actions differ. Touches core `FLAG_TYPES` in `packages/core/src/types.ts` + `flags.ts`, the key map in `src/renderer/flags.ts` (**N** = rename, **T** = date; D/E/M/R/O/Q/S are taken), and the queue window UI.

### Settings answers & tweaks
- **Cluster cap**: yes, there is a max — the setting is clamped 2–100 (`src/main/settings.ts`). Keep 100; surface "2–100" as inline hint text in the settings form so the question answers itself.
- **Video cap**: adopt **0 = play full length**. Add a sentinel path in `settings.ts` (today min-clamps to 2) and in the cap timer (`src/renderer/video.ts` `createVideoWatch`); hint text "0 = full length" next to the field. Blank is ambiguous; an explicit 0 is not.

### Startup time (first pass)
- Show the window immediately and start the show against the **persisted EXIF index** (`src/main/indexer.ts`) instead of blocking on the full recursive `scanMedia`; rescan in the background and merge new files in. Full profiling is deferred (see roadmap) — this alone should cut most of the perceived delay.

### "Set as screensaver" (Windows first; testers OK'd requiring the installer)
- **A "Set as default screensaver" button in settings** (Windows): ship a thin `.scr` wrapper (a stub that launches the installed Afterglow with `--show`) placed by the NSIS installer; the button registers it via the registry (`SCRNSAVE.EXE` / `Control Panel\Desktop`) and reports current status. Because the `.scr` just launches the real app, **screensaver mode always uses the same settings store** — the sync testers asked for comes free.
- Screensaver mode covers the primary display for now; full multi-monitor support stays at its roadmap slot.
- Linux idle-hook and macOS guidance stay on the roadmap (v0.9); the button is hidden on non-Windows.

*Done when: a tester lands in settings on launch, starts the show, steps back two photos with ←, skips a moment with ↓, flags one photo N for rename, escapes back to settings — then clicks the screensaver button, waits out their idle timeout, and Afterglow starts as the system screensaver with their configured settings.*

## Mobile m0.5 — "Feedback: trust the user"

Files referenced are under `apps/mobile/src/`.

### Editor launch fallback (Samsung bug)
- In `lib/edit.ts`, when `ACTION_EDIT` resolves no activity, **fall back to `ACTION_VIEW`** (opens Samsung Gallery / default viewer, where the pencil is one tap away) before ever showing an error. The remaining error loses the confusing "or enable" wording and just says no viewer/editor was found. No new settings — the fallback chain makes an "editor picker" setting unnecessary for now.

### Similarity rescale + slider
- **Shift the whole scale looser** per the guidance (identical photos must group at Strictest). Current steps in `lib/similarityPrefs.ts` are 4/8/12/18/26 (max Hamming distance on the 64-bit dHash); new five-step mapping: **Strictest 12 · Strict 16 · Normal 20 · Loose 26 · Loosest 32** — old Normal becomes the new Strictest and the top end stays temporal-proximity-dominant, matching what testers observed. Keeping 5 levels since the chips already exist.
- **Add a fine-tune slider (0–64)** beneath the chips in `SettingsScreen.tsx`; chips snap the slider to presets, slider selects "Custom" when off-preset. Persistence already accepts any int 0–64 (`parseSimilarityThreshold`), so this is UI-only. A one-line explainer ("higher = groups more different-looking photos") answers the "what's happening under the hood" curiosity.

### Reversible decisions
- **Any photo's decision can be changed until the final cull confirmation.** Add re-decide transitions to core `DeckSession` (`packages/core/src/deck.ts`) — e.g. `to_edit` → staged-cull, staged-cull → keep — and expose them in the deck/group UI (tap a decided photo → chip row to change state). This also underpins "starting a new session must not discard decisions" below.

### Session flow freedom
- **Free ordering**: from the Groups screen, enter **any** group (stop forcing `currentGroupId()` in `DeckScreen.tsx`), and allow **doing singles before groups** (Home/Groups exposes both entry points). "Doing something, no matter the order, is better than doing nothing."
- **"Replace unfinished session?" dialog** (`HomeScreen.tsx`): reorder so **Continue existing** is the right-most/default action, Cancel beside it, "Start new" on the left.
- **Starting a new session never discards decisions**: decisions made in the old session are committed to the store (they're persisted per-photo in SQLite via `db/store.ts`) rather than dropped with the session snapshot.
- **End session early**: an **"End session & apply"** action that locks in all decisions made so far and jumps to the staged-cull confirmation. Fatigue after 10 groups is normal; progress must be bankable.

### Session size settings (new "Sessions" section in Settings)
- **Max photos per session** — default **50** (replaces the hardcoded `SESSION_PHOTO_CAP = 500` in `lib/reviewLoader.ts`).
- **Group-boundary inclusion** switch (default on): if the cap lands mid-group, include the whole group (cap becomes soft by up to one group).
- **Oldest first / newest first** selector for which photos a session draws.

### Compare fixes
- **Two-photo groups**: choosing "X is better" marks X **best of group** and offers to cull the other — confirmation dialog with a **"don't ask again"** checkbox (resettable in Settings). With "don't ask again" on, better = auto-cull the loser, matching tester intuition.
- **Larger groups**: "X is better" now has visible meaning — it stars X as current best-of-group candidate and feeds Reconsider, with a toast saying so (today it silently records a duel, which read as "no effect").
- **Opponent choice**: make the existing long-press-to-pick-opponent discoverable — an explicit "Compare with…" affordance in the deck/compare entry, not just an undocumented gesture.
- **Keep group numbers**: compare labels show the photos' group indices (e.g. "3 vs 7") instead of A/B, so testers can find them again after leaving compare (`CompareScreen.tsx`).

### Review scopes
- **Customizable review scopes**: named custom scopes with a date range (e.g. "Japan — Jan 31 to Mar 6") created from the custom-scope screen and persisted; Settings gains a scope manager to enable/disable/delete scopes and reset to defaults. Replaces the static `SCOPE_DEFS` array in `lib/scopes.ts` with store-backed defs seeded from the defaults. Start Home with 2–3 enabled + "Custom".

### Group review zoom
- **Pinch-zoom in group review**: bring Compare's synchronized-zoom gesture into the deck. The deck pager and pinch gestures conflict (the code comments call this out), so this needs real gesture-arbitration work — the riskiest item in m0.5; if it drags, it's the designated cut line.

### Small stuff
- **Settings icon → an unmistakable gear** (current one reads as an eye/sun).
- **Remove Source from the Home screen** — it lives in Settings already.

*Done when: a Samsung tester taps Edit and lands in Gallery; two identical photos group on Strictest; a tester does singles first, changes a to-edit photo to cull, ends the session after 3 groups without losing a single decision, creates a "Japan" scope, and pinch-zooms right in group review.*

## Updated release roadmap

Mirrored in [PLAN.md](../PLAN.md), which is the canonical roadmap.

**Desktop:** v0.5 feedback release incl. screensaver (Windows) → **v0.6 RAW pipeline** (was v0.5; still the flagship, still budgeted a real week) → v0.7 organizer mode → v0.8 retrospectives + multi-monitor + polish → v0.9 Linux/macOS screensaver paths + auto-update → v1.0 hardening/signing.

**Mobile:** m0.5 feedback release (everything above) → m0.6+ stats/streaks, deeper perf work, fixes from field use, then evaluate iOS.

## Deferred to roadmap (not in these versions)

- **Desktop startup profiling beyond the index-first change** — if v0.5's change isn't enough, a dedicated perf pass rides with v0.6 (the RAW pre-render queue touches the same startup path).
- **Linux/macOS screensaver integration** — v0.9; Windows first, per both the feedback and the original plan.
- **Editor "enable/pick" setting on mobile** — reconsider only if the ACTION_VIEW fallback still leaves testers stuck.

Everything else from Feedback_20260717.md ships in v0.5 / m0.5.
