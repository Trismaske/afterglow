## Autonomous decisions (appendix) — ALL VETTED (grilling, 2026-07-29)

Numbered as they are implemented; planning-stage flags above are the pre-implementation log.
**Vetting outcome:** every entry below is settled — explicitly approved earlier (1, 4, 6, 28, 34), settled in the closing grilling (11: no-selection convention accepted + queue-alignment TODO; 16: superseded by the endpoints-cover-alive whole-table rule; 17: "N is better" moved to the accent), superseded by accepted review-round rework (3: read-time tails; 9/15/21/32: the gate choreography was rewritten over them), or exercised without objection across nine review rounds and Tristan's device passes (the remainder). Nothing here is an open assumption; the file deletes whole when m0.8.2 ships.

1. **(Phase 1) Undated photos interleave by their fallback timestamp**, superseding the planning flag "undated sort last": every photo carries `taken_at = DATE_TAKEN ?? DATE_MODIFIED`, the feed already orders undated rows by it, and forcing them last would break the merge order. They form runs under the undated pseudo-day wherever their timestamps land. **Approved (Tristan, 2026-07-29).**
2. **(Phase 1) Timeline ties break toward the single**: a single sharing a group's anchor timestamp closes its run before the group, keeping a burst's stragglers ahead of the burst. Either order is defensible; this one is pinned by test.
3. **(Phase 1) Horizon truncation**: when either bounded page (100 groups / 500 singles) is full, units older than the older page's tail are dropped — placing them would invent an order the DB does not hold; the tail pages in as units complete. A run straddling the horizon keeps its surviving members.
4. **(Phase 1, OVERRULED by Tristan 2026-07-29) Every deck reads NEWEST-first** — the most recently taken photo first, in singles runs, day decks AND groups (member order flipped at the store, so cards, Compare labels and timeline anchors all follow). The original autonomous call (chronological oldest-first everywhere) is gone.
5. **(Phase 1) Every deck opens on its first PENDING photo** (both kinds) instead of index 0, so re-entering a half-finished unit lands on the work, not on a decided photo.
6. **(Phase 1) The live singles deck's Edit chip is now a flag toggle** (`toggleNeedsEdit`) like the group deck's, replacing its old keep-and-queue-edit verdict write — Q2's "port group-deck semantics wholesale". The verdict layer is untouched by the chip; browse mode keeps the state-aware re-decide path. **Approved (Tristan, 2026-07-29).**
7. **(Phase 1) `releaseBrowseIds` anchors on Home regaining focus**, not deck unmount: a deck→deck `replace` runs the new deck's load before the old deck's cleanup, so an unmount-time clear would wipe freshly installed overlay ids.
8. **(Phase 1) Run identity is day + taken_at range OVERLAP**: a rebuilt run's pending-only range can only shrink inside the range its deck opened with, so overlap-matching survives mid-run keeps; a vanished run advances from its former timeline index (the dissolved-group semantics, generalized).
9. **(Phase 1) The UI gate's first-card anchor accepts `Group ·` OR `Singles ·`** — the merged timeline may put a run first, and the unified deck passes the same steps either way.
10. **(Phase 2) A target-less re-queue after a completed move keeps the LAST target as a prefill** (`ON CONFLICT` leaves `target` alone): the queue screen shows it and one selection re-assigns, which beats wiping a probably-still-right album. Pinned by test.
11. **(Phase 2) The organize queue adopts share's "no selection = everyone" convention** for Choose album and Remove — one selection language across the two grids, and batch assignment over the whole queue is the common case.
12. **(Phase 2) Cell album tags show the target path's last segment** in the organize hue ("No album" stays neutral; a failed row adds a red badge) — the full path lives one long-press away in the viewer's detail panel.
13. **(Phase 2) `setOrganizeTargets` resets an errored row to `queued`** — a new album is a fresh intent, so the failure state does not outlive the intent it described.
14. **(Phase 2) `applyPhotoSingles` chunks at 300 ids** (3 interpolations × 300 < SQLite's 999-parameter floor); sequential chunks compose because earlier ejections are already `group_id = NULL` when later chunks compute survivors.
15. **(Phase 2) UI-gate reshuffle**: the deck Organize step joins the plain-chip loop (it is a toggle now), the album-picker step moves to the Organize queue (mutation-free open/cancel, empty-state aware), and the staged-cull badge assertion now covers Organize too.
16. **(Phase 3) "Whole table" for the group dialog means ≤ 2 ALIVE (undecided) members**, not exactly 2: F11 lets kept members rejoin a duel, and a duel that settles the group's undecided remainder is the decision moment even when a kept photo is one endpoint. Browse-mode duels (0 alive, two kept members) get the dialog too — long-press compare now works in browse.
17. **(Phase 3) The singles "Keep N" button became "N is better"** — the dialog carries the verdict question now, so the button must not promise a keep it might not write.
18. **(Phase 3) Compare position labels number over ALL group members / the deck's own day-or-run rows** (the run range rides the Compare route), matching the unified deck's numbering — the old unreviewed+culled ordering disagreed the moment a kept member became comparable.
19. **(Phase 3) The four deck/Compare action chips are ONE component** (`components/ActionChip.tsx`) — eight hand-rolled chip blocks in the deck and Compare's two odd tags collapsed into it (F16's consistency enforced structurally).
20. **(Phase 4) Home's CTA falls back to the overview** when the timeline page is empty but the DB count is nonzero (every pending unit beyond the horizon) — never a blind CullList jump.
21. **(Phase 4) The UI gate collapses "continue → queue → first card" into one direct-to-deck step** and gains a queue-breakdown → overview step, keeping overview coverage the direct CTA no longer provides.
22. **(Phase 5) Conditional blocks (coverage card, cull row, scan line, detection banner) deliberately do NOT ghost**: ghosting a block that may resolve to absent trades an insert for a removal — same shift, plus a lie. Ghosts cover only blocks that will exist (goal card structure, Progress row, day sections).
23. **(Phase 5) The goal ring renders "–" until its loader's first commit** — a hardcoded "0 of 50" is a wrong number, not a loading state; the loader's two commits were merged into one batched commit while in there.
24. **(Phase 6) A delta pass keeps `total` null** (plain counts, no percent): its honest denominator is a handful of ranges, and delta passes are seconds long — carrying a pass-coverage estimate bought a percent nobody would see. The library snapshot (`corpusTotal`) is fetched AFTER the skip check so an unchanged open stays one native call, and planPass's tripwire count reuses it via the 20 s cache.
25. **(Phase 6) The delta→full fallback resets `scanned` (with a fresh denominator) but deliberately NOT `windowsGrouped`** — the refresh subscribers diff windowsGrouped, and a rewind would silence them until the new run caught up past the old value. This amends the planned "reset all pass counters together" rider with the reason the plan missed.
26. **(Phase 6) brace-expansion's advisory widened to `<=5.0.7`** while taking the fast-uri fix — TODO's audit-gate entry updated; the gate stays at `critical` (still no backport, dev tooling only).
27. **(Phase 7) Personal records are computed per stats tab** (Activity and Habits each run `personalRecords` over their own unbounded decision-day read) — the one-loader-per-tab doctrine outranks sharing a ~ms aggregate. Activity's `reviewedByDay` became all-time; windowed consumers keep reading their own keys out of the map.
28. **(Phase 7, AMENDED per Tristan 2026-07-29) The celebration counter lives in ReviewContext**, not the deck: his blocker — cross the goal on the Compare screen, leave review, and the moment never fires — was real. Every verdict-writing surface calls `noteDecisions(n)` with its fresh-decision count (deck taps, batch keeps, Compare's dialog outcomes), the crossing arms a consume-once flag, and whichever surface is FOCUSED claims and renders the overlay — so a Compare crossing celebrates on Compare, instantly. Still source-unscoped, still once per day via `goal_celebrated_day`.
29. **(Phase 7) The celebration animates entirely from JS** (shared values written in an effect, `setTimeout` ends it) — no `runOnJS`, extending the deck's bridge rule to animation callbacks even though only gesture callbacks are known to crash.
30. **(Phase 7) Terminology sweep applied**: "staged for deletion" → "staged to cull" (Home, CullList, Stats); "waiting" → "queued" everywhere user-facing (Habits turnaround lines, Stats card title "Waiting for you" → "Queues", Edit/Favourite queue empty/subtitle copy, share subtitle's bare count); the queue-screen headings already conformed. The `Turnaround.waiting` field name stays — DB/internal identifiers were never the rule's target.
31. **(Phase 8) UnitCard thumbnails cap at a third of the card width** — a one-photo timeline run rendered a full-width, screen-filling square (device-observed on the overview: two cards per screenful); strips of three or more are unaffected.
32. **(Phase 8) Gate choreography made unit-shape-proof**: the deck flow records its actual start position (the unified deck opens on the first pending photo), reroutes when the head unit cannot host the cull-advance assertion (< 2 photos, or the pending photo is last), and accepts ANY unit with ≥ 3 photos — a multi-photo singles run reviews exactly like a group. Device-observed failure mode: a one-photo run at the timeline head silently degenerated the whole flow and failed the badge assertion on actions that were never culled away.
33. **(Phase 8) The gate force-stops known PiP apps at start** — a YouTube picture-in-picture window floated over the title-row icons and ate the Stats tap without ever taking the foreground, which the existing theft detector cannot see.
34. **(Phase 8, settled by Tristan)** One-photo singles runs stay as-is for m0.8.2 — a sparse-photo stretch produces one card and one tiny deck per day, which is honest capture-order review, just ceremonious; auto-advance chains through them. Coalescing adjacent small runs across days was considered and declined (it blurs the day model Q12 chose). Revisit only if testers complain.
